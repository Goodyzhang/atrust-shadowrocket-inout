## 1. 先检测，再修改

只读取能改变下一步选择的信息：

1. 已安装的 Docker/OrbStack/Desktop、当前 context、真实 aTrust 容器/镜像与架构、运行状态、端口映射、持久状态目录。按字段读取，不整份输出容器环境变量、凭据或订阅配置。确认镜像确属 docker-easyconnect 后，才采用该项目的对应说明。
2. 通过支持的 UI 核对已有 aTrust 登录状态，保留登录。登录成功不等于目标可达。
3. Shadowrocket 当前 profile、相关规则顺序、代理协议/端口、系统代理/TUN/bypass 与已有外网路径。使用支持的 UI/导入/配置接口，不直接修改其正在使用的私有数据库。
4. 已有 Mihomo 或其他本地桥接代理的进程、实际配置路径、监听、上游和启动机制，不启动第二个抢占端口的实例。
5. 目标应用代理配置的生效范围及实际执行主机。远程扩展宿主、容器和本机的 loopback 各不相同。

只补问缺少的必要信息：已授权目标、缺失的 VPN 门户/账号、需用户完成的登录/MFA 或应用凭据。不把其他服务密码当成 VPN 密码。让用户在支持的安全界面输入秘密，不要求发送到聊天、不放入 shell 参数或日志。优先使用 Keychain/SecretStorage；如果上游镜像要求本地凭据文件，放在仓库外、限制权限，说明本地管理员仍可能访问，禁止输出文件内容。

## 2. 选择并实测一条路径

先对已授权目标执行限时 TCP/SSH/TLS/HTTP 检查，分开验证宿主机直连与显式 SOCKS，不只依赖 ping 或 VPN 登录状态。

- 已有宿主机路由确实满足目标应用时，保留它。
- 只有 aTrust SOCKS5 可达时，确认实际发布端口并实测 SOCKS 协议。本机代理监听不会让远端 IP 变成本机地址。
- 浏览器/应用已经遵循 Shadowrocket 时，将实测 SOCKS5 入口加入节点，并添加精确内网目标规则。
- 仅当应用需要合适的显式 HTTP 入口或现有方案确需它时使用 Mihomo。内网 TCP 请求送入只含 aTrust 的策略，其他请求送往已有且实测的 Shadowrocket HTTP 入口。本方案保持 Mihomo TUN 关闭，不让 Shadowrocket 的上游再回指 Mihomo。

不假定端口是 `1080`、`1082`、`7890` 或历史值；不假定系统 HTTP 代理或 `ALL_PROXY` 会配置 OpenSSH。需要时先检查本机 `nc` 能力，再按单个 Host 配置 SOCKS ProxyCommand，保留身份和严格主机键校验。

VPN 登录有效但目标不通时，检查容器到该准确目标的路由。VPN 缺少资源授权/路由或网段冲突尚未解决时，报告具体条件，索取管理员提供的可路由地址、路由或已授权跳板。不虚构可用地址，不反复重装依赖。

## 3. 只改接入所需内容

将要修改的文件/设置备份到本仓库外的私有目录，保持严格权限；记录位置和精确恢复方法，不把秘密复制到报告。保留无关字段与规则。

已有 aTrust 部署复用镜像、会话和持久状态，不为套模板而替换或重建。绑定方式或运行时调整若会中断现有连接，应明确影响，利用约定的维护时机执行。

确实尚未部署时，核对镜像当前上游说明及架构支持。随包 Compose 只适用于指定的 docker-easyconnect aTrust 镜像系列。选择已核验的 tag/digest 与平台，建立私有状态目录和环境文件，启动前验证配置，SOCKS 与登录 UI 只绑定 `127.0.0.1`。使用文档中的最小必要 capability 与 TUN 设备，不默认增加 `--privileged` 或 host networking。VPN 登录/MFA 交由用户完成，容器创建成功不算验收通过。

先建立内网策略，再在规则中引用。该策略只含 aTrust 上游，内网 TCP 不自动回退 DIRECT 或外网代理。把精确域名和 `/32` 规则放在会绕过它们的规则前，不未经核对就添加全部 RFC1918 网段。保留外网路径与订阅更新。记录范围限制：绕过代理的应用、UDP、QUIC、WebRTC 与系统 DNS 不在本 TCP 方案验收范围内。

把示例片段按实际值合并到私有生效配置，不整份替换现有 profile/settings，端口使用实测值。不能通过关闭 TLS 校验修复证书错误。确需组织 CA 信任时，取得并核验批准的证书，采用其支持的安装流程。

只修改需要的应用代理范围。内网 AI provider 保留完整模型 ID，并确认客户端 base URL 约定；API Key 使用客户端安全存储。连通性检查不附带工作区或文件内容。

## 4. 实际验收

先用已安装工具验证配置，再验证真实应用。请求保持小、限时且仅针对用户目标。以下各项分别记录 PASS / FAIL / NOT RUN：

1. 运行时/容器状态及准确 loopback 监听协议与端口。
2. aTrust SOCKS 对每个必要内网目标的访问、实际服务身份和目标端口。
3. 最终选定路径（Shadowrocket 或可选 HTTP 桥接），可观察时记录命中策略。
4. 外网仍走既定路径并可访问。
5. OA：必要 SSO 跳转、落地页与指定嵌入应用，只检查脱敏的主机/端口/状态元数据。
6. 内网 AI：准确 provider/model 的已认证最小文本响应；有要求再测流式与客户端取消。未认证 `401` 或模型菜单加载不足以通过；未测不宣称支持工具、视觉、长上下文或服务端取消。
7. GitLab：使用已有认证对目标仓库完成只读操作。SSH 还需独立核验主机键、授权客户端公钥，不为连通性测试 push 或改历史。
8. 约定的启动行为：复用现有服务管理器，有限范围 reload/restart 不干扰无关工作，可能中断的重启先安排。核对实际恢复的部分，说明是否需重新登录 VPN；未实测不宣称重启系统/休眠恢复已通过。

分清超时/拒绝、SOCKS 错误、VPN 路由、TLS、应用认证与模型权限。工具被 sandbox 拦截时，先通过正式提权机制核对，再判断网络。失败后保留安全证据，定向修改并重测受影响项。应用不支持或缺少 UI 访问时如实报告，不假称完成界面验收。

## 5. 留下可复用的私有交接

按 `docs/acceptance-template.md` 的结构生成本机私有报告。真实地址与私有备份放在仓库外、不进 Git，并给我报告绝对路径。

报告包含实际链路与协议、实测监听端口、生效配置位置、版本、启动/重新登录顺序、不含秘密的限时诊断命令、回滚方式、各应用结果和具体剩余条件。区分教程示例、已观察事实与未验证假设。

在该 harness 现有本地规则里增量添加指向私有报告的简短约定，保留原内容和作用域。使用它实际支持的机制，不向其他 agent 强装 Codex 专用插件/MCP。找不到明确规则位置时，提供私有交接文件并解释复用方式，不宣称自动加载成功。同一组本机 CLI/配置路径可由其他已授权的本地 agent 复用。

最后简洁报告改了什么、哪些实际通过、哪些未测或受阻、以后如何恢复。没有真实配置并验证调度器，不承诺会话结束后继续监控。不留下空轮询或临时测试服务。
