## Procedure

1. Locate this tutorial and read `docs/copilot-claude.en.md`, applicable local rules and the existing private access report. Discover the actual user, HOME, OS, VS Code profile, client/Copilot versions and extension execution location. Do not copy example ports or paths.
2. Use supported UI to check the actual GitHub account, Copilot plan, model entitlement, organization policy and usage limits without exposing tokens. Record the symptom and reproduce once in a window with no project. Distinguish missing catalog entries, Upgrade entries and failed requests after selection. Success on another machine is a comparison clue.
3. Read relevant proxy fields, listeners and effective rule matches. If necessary, open the installed version's Copilot Output channels and inspect only the relevant time interval, error category, catalog state, model identity and destination. Do not dump whole logs, environment variables, cookies or credential databases.
4. Establish the actual path. If an explicit proxy is needed, verify VS Code → existing local HTTP entry point → intended Internet upstream → GitHub Copilot. Retain an adequate existing path; do not install Mihomo merely to reproduce the case. With Mihomo, inspect the selected policy; also check the real request domain against Shadowrocket's active configuration. The case's `api.individual.githubcopilot.com` and `githubcopilot.com` are observed targets, not a complete list for every version. Consult current official endpoint guidance instead of routing all GitHub traffic blindly.
5. Use the case's bounded `_ping` probes when they change the next decision, retaining TLS verification. A listener, an HTTP response, a refreshed catalog and Claude generation are separate checks. Handle sandbox restrictions through the harness's formal permission mechanism before diagnosing a network failure.
6. Once evidence identifies a configuration problem, back up privately and change only the relevant field/rule. If DIRECT/bypass sends an actual target along a failing path, select an already defined, usable Internet policy and retest. Do not change every DIRECT rule to PROXY, send public Copilot targets into the company VPN, recreate aTrust or add a second global TUN.
7. Check VS Code's effective settings scope and incrementally merge the HTTP entry point and `http.proxySupport` when needed. Preserve JSONC comments and unrelated settings; retain `http.proxyStrictSSL: true`. The `override` value does not replace actual request verification. Evaluate remote extension-host loopback separately. Do not use a SOCKS listener as an HTTP port, disable certificate checks or fabricate account/model entitlement.
8. If compatibility requires an update, use official channels and a suitable current version. Save work, reload an idle window or arrange a restart. Record before/after versions and fetch fresh model metadata. Prefer one change and retest at a time; disclose concurrent changes instead of claiming a unique root cause. Do not erase the whole login cache, profile or authentication database.
9. In a project-free window, use the installed version's Ask/ordinary chat mode with file/workspace attachments disabled. Select the intended Opus actually available to the account and ask “Reply only with OPUS_OK”; select Sonnet and ask “Reply only with SONNET_OK.” Correlate selected model, UI reply and same-time model identity/success logs. If UI access is unavailable, disclose that limit; do not simulate a response or repeatedly consume quota.
10. Recheck necessary public access and an existing internal path. Preserve the company provider's key/secure storage and aTrust session. Label an unauthenticated probe as transport-only, not full model-workflow regression. Do not start training, write business data or upload project files.

## Deliverable and limits

Save a private report outside this checkout with symptoms, account-entitlement conclusions without credentials, listeners/policies, before/after versions, exact changes, rollback, and each model's time, identity, UI result, log status and evidence limits. Mark untested models, tools, vision, long context and sustained availability NOT RUN.

For missing sign-in/MFA, have the user complete the secure UI. For organization or service-side entitlement gaps, report the precise condition without repeated reinstallation, extra purchases or bypasses. Keep raw logs and full proxy profiles out of the public repository.

Finish with PASS / FAIL / NOT RUN for the checks and confirm cleanup of temporary test resources. Do not restore a broken setup merely to isolate causality after recovery. Rollback restores only this task's fields/rules and preserves later user changes. Leave no idle polling and promise no background monitoring unless it was configured and verified.
