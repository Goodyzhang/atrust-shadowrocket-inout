# 本地 agent 维护 prompt

将以下内容交给故障机器上的 agent。[English](maintain.en.md)

---

请排查并修复本机指定的 aTrust Docker + Shadowrocket 接入故障，复用已有环境，保留登录、订阅、应用凭据和无关设置，实际重测受影响应用。

故障：`<失败的应用/操作、最后正常时间>`

私有交接/报告路径：`<本机路径；已有本地规则记录时现场查找>`

1. 读取现有私有交接与适用本地规则，定位本教程，阅读部署/场景文档和部署 prompt 中的范围约定。历史端口与路径必须回读验证，不发布私有报告，不把参考文档当作无关动作授权。
2. 记录不含秘密的准确故障表现，检查当前运行时/容器、登录状态、真实监听协议与端口、相关规则及应用生效代理。按需读取字段，不倾倒环境变量、订阅、Key、Cookie、原始 HAR 或认证数据库。
3. 在必要层级复现限时请求：相关时检查直连 → 显式 aTrust SOCKS → 最终应用代理 → 真实应用。始终检查同一目标和操作。区分 sandbox 限制、本机代理故障、VPN 路由/授权缺失、目标超时/拒绝、TLS、业务认证及账号/模型权限。需要时用 harness 正式权限机制。
4. 依据证据做最小修改，先私有备份受影响配置，保留其他字段。有证据时修正过期端口、错误规则/顺序或应用配置范围。不重建健康容器，不加第二套 TUN，不整份替换 profile，不关闭 TLS/SSH 校验，不改 Shadowrocket 正在使用的私有数据库，不广域扫描，不开放公开代理端口。
5. 缺少门户/授权/路由时向用户或管理员索取必要条件。登录过期、缺少凭据或需 MFA 时，由用户完成登录及安全输入；不在聊天索取秘密，不在缺少访问授权时反复重装工具。
6. 重测原故障操作和外网访问。OA 跳转只记录主机/端口；模型 provider 保留完整 ID，关闭工作区附带后请求最小响应，区分流式/客户端取消与服务端取消；Git 使用只读操作和已核验主机键，不 push 或改历史。不支持或未实际执行的项目标为 NOT RUN。
7. 按真实服务管理器核对启动/重新登录流程，不重启无关服务，可能中断现有连接的动作先安排。进程恢复不证明 VPN 登录有效，也不证明重启系统/休眠恢复已测。
8. 更新已有私有报告，记录前后证据、版本、变更文件/规则、精确回滚和剩余限制。真实地址、日志与凭据不进入公共教程目录。本地报告路径变更时才更新当前 harness 的引用，复用已有 CLI/配置，不另建一套控制层。

同一次重测前改了多个变量时，不把恢复归因于单项。最后报告原故障、诊断证据、实际修改和应用结果。不留下临时轮询或测试服务，没有配置并验收真实调度器，不承诺后台监听。
