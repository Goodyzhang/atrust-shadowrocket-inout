# VS Code Copilot Claude 专项修复 prompt

[English](copilot-claude.en.md) · [案例与操作说明](../docs/copilot-claude.zh-CN.md)

把分隔线以下内容交给故障机器上的本地 agent；本教程需已下载。不必提供 Anthropic API Key，不在聊天中发送 GitHub token、VPN 密码或代理订阅。

---

请实际排查并修复本机 VS Code Copilot 中 Claude 模型缺失或不可调用的问题，复用已有 Shadowrocket、aTrust Docker 和可选 Mihomo。不要只给教程，也不要把历史成功案例当成本机已经通过。

我的症状：`<例如已有 Pro+，另一台机器可以使用 Opus，本机缺失 Claude/只显示 Upgrade/调用失败>`。

希望验收的模型：`<当前账号提供的目标 Opus 与 Sonnet；具体型号现场核对>`。

我授权本任务必要的本地增量配置、官方客户端/扩展更新，以及每个目标模型一次最小文本请求。请求会计入现有账号用量，不购买套餐或额外额度。可能中断其他工作的更新/重启先安排，保留已打开文件与现有会话。

## 工作流程

1. 找到本教程并读取 `docs/copilot-claude.zh-CN.md`、相关本地规则及已有私有接入报告。检测实际用户、HOME、OS、VS Code profile、客户端/Copilot 版本和扩展运行位置，不能照抄示例端口或路径。
2. 通过受支持界面核对实际 GitHub 账号、Copilot 套餐、模型权限、组织策略和用量限制，不输出 token。记录失败表现，在无项目窗口复现一次。分清目录缺失、Upgrade 入口和已选模型请求失败；用户在另一台机器可用只是比较线索。
3. 读取相关代理字段、实际监听与规则命中。必要时打开 VS Code Output 中当前版本提供的 Copilot 日志通道，只查看目标时间段的错误类别、目录状态、模型 ID 和连接目标；不倾倒完整日志、环境变量、Cookie 或凭据数据库。
4. 确认实际路径；需要显式代理时核对 VS Code → 已有本机 HTTP 入口 → 正确外网上游 → GitHub Copilot。已有路径足够时保留，不为复刻案例另装 Mihomo。使用 Mihomo 时，观察其命中策略；同时对真实请求域名检查 Shadowrocket 活动配置。案例中的 `api.individual.githubcopilot.com` 和 `githubcopilot.com` 是已观察目标，不是所有版本完整清单。核对当前官方端点说明，不盲目给所有 GitHub 流量加规则。
5. 需要时使用案例里的限时 `_ping` 检查分层定位，保留 TLS 校验。代理口有监听、curl 返回 HTTP、模型目录刷新、Claude 生成成功分别验收。sandbox 拒绝用 harness 正式权限机制处理，不误判为网络故障。
6. 找到配置问题后先私有备份，只修相关字段或规则。若真实目标被 `DIRECT`/bypass 送到有问题的路径，改为已定义且可用的外网策略并重测。不要无条件把 `DIRECT` 都改为 `PROXY`；不把 Copilot 公共目标送进公司 VPN，不重建 aTrust，不增加第二套全局 TUN。
7. 核对 VS Code 生效代理作用域，按需增量合并 HTTP 入口及 `http.proxySupport`。保留 JSONC 注释和其他设置，保持 `http.proxyStrictSSL: true`。`override` 不替代实际请求验证，远程扩展宿主的 loopback 需单独判断。不把 SOCKS 端口当 HTTP 端口，不关闭证书校验、不伪造账号或模型权限。
8. 若需处理版本兼容，通过官方渠道更新到适用版本，保存工作后重载空闲窗口/安排重启。记录变更前后版本，重新获取模型目录。尽量一次改一项并重测；多个变量同时变化时如实记录，不声称已定位唯一根因。不删除整个登录缓存、profile 或认证数据库。
9. 在无项目窗口使用当前版本支持的 Ask/普通聊天模式，关闭文件/工作区附带。选择账号实际可用的目标 Opus，发送“只回复 OPUS_OK”；再选择目标 Sonnet，发送“只回复 SONNET_OK”。结合选中模型、UI 回复及同时间日志中的模型身份和成功状态，核对真实生成。没有 UI 权限时说明这项限制，不用脚本模拟响应冒充 UI 通过，也不循环消耗额度。
10. 回归必要的外网访问和已有内网路径。保持公司 provider 的 Key、安全存储和 aTrust 登录不变；无认证探测仅记录网络可达，不宣称完整模型业务回归。不启动训练、业务写库或上传项目文件。

## 交付与边界

将报告保存到仓库外的私有目录，记录症状、实际账号权限结论（不含凭据）、监听/策略、变更前后版本、精确改动、回滚方法，以及每个模型的时间、型号、UI 结果、日志状态和证据边界。其他模型、工具、视觉、长上下文及持续可用性未测则标 NOT RUN。

缺少登录/MFA 时让用户在安全 UI 完成；缺少组织权限或服务端授权时报告具体条件，不反复重装、继续购买或规避限制。原始日志和完整代理配置不进入公共仓库。

最后报告哪些检查 PASS / FAIL / NOT RUN，确认临时测试资源已清理。恢复可用后不为证明单一原因再切回故障环境；回滚只还原本次字段/规则，不覆盖用户后续配置。不留下空轮询，不承诺未经配置验收的后台监听。
